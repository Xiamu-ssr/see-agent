## 1. 设计目标

### 1.1 核心问题

v3.2 虽然实现了事件驱动和常驻进程，但仍存在架构性问题：

| 问题 | 表现 |
|------|------|
| **team 耦合** | agent 必须通过 TeamManager.run(task) 触发，无法独立私聊 |
| **双目录混乱** | `agents/` 存定义、`teams/xx/agents/` 存运行数据，前端 bug 频出 |
| **消息源分裂** | user_queue、TeamBus、TaskBoard 三个独立消息通道，drain 逻辑分散 |
| **提示词写死** | 15 条 RULES 硬编码在 prompts.py，用户无法定制 |
| **新消息并发** | loop 执行中来了新消息，没有 steer/collect 策略 |

### 1.2 目标

1. **agent 是独立实体**：每个 agent 可独立私聊，不依赖 team
2. **统一消息通道**：所有消息来源归入一个入口，前缀区分
3. **collect + steer 双模式**：默认 collect 排队，支持 steer 插入当前 loop
4. **单一目录**：agent 数据只在 `agents/{id}/` 下，team 是轻量引用
5. **workspace 驱动提示词**：代码不写死规则，AGENTS.md/SOUL.md 等文件注入
6. **独立进程 + sandbox**：每个 agent 一个进程，sandbox-exec 隔离（沿用 v3.1/v3.2）
7. **server 做消息路由**：中心化邮局，所有 agent 间通信经 server 转发

### 1.3 设计哲学

- 参考 OpenClaw：workspace 文件注入提示词、Gateway 常驻 + agent loop 按需触发
- 参考 OpenClaw command queue：collect/steer 消息排队策略
- 参考 AutoGen：actor model，agent 只有一个消息入口
- agent 独立进程保留（v3.1/v3.2 已实现），因为需要 sandbox-exec 进程级隔离
- team 像游戏房间，agent 加入/退出不影响自身数据

## 3. 模块一：统一消息通道 + collect/steer 双模式

### 3.1 统一消息结构

所有消息来源统一为 Message 结构，通过 UDS 发给 agent 进程：

```python
@dataclass
class Message:
    source: str        # 消息来源类型
    sender: str        # 发送者标识
    content: str       # 消息内容
    priority: str      # "normal"(collect) 或 "steer"(注入当前loop)
    metadata: dict     # 附加信息（team_id、task_id 等）
    timestamp: str     # ISO 时间戳
```

### 3.2 消息来源与前缀

| source | sender | 注入前缀 | 场景 |
|--------|--------|---------|------|
| `user` | `lanxuan` | `[user lanxuan]` | 用户私聊或在 team 中发消息 |
| `leader` | `alice` | `[leader alice]` | team leader 发来的指令 |
| `teammate` | `bob` | `[teammate bob]` | team 同事发来的消息 |
| `task` | `system` | `[task]` | 任务分配/状态变更通知 |
| `system` | `system` | `[system]` | 心跳、配置变更、屏幕可用等 |
| `remote` | `charlie@mac2` | `[remote charlie@mac2]` | 远程 agent 消息（未来） |

规则：
- 用户消息永远是 `[user xxx]`，无论 agent 在不在 team 里
- leader 和 teammate 仅在 team 上下文中出现
- agent 不需要知道消息从哪个 API 进来，只看前缀

### 3.3 collect/steer 双模式

**默认为 collect**，发送方可显式指定 `priority: "steer"`。

| 模式 | 触发条件 | 行为 |
|------|---------|------|
| **collect** | priority="normal"（默认） | 消息排队，当前 loop 结束后，所有排队消息合并成一轮新 loop |
| **steer** | priority="steer"（显式指定） | 消息注入当前 loop 的 inject 队列，下一步 LLM 调用就能看到 |

#### agent 进程内部实现

```python
class AgentRuntime:
    def __init__(self, agent_id, uds_client):
        self._running = False
        self._pending: list[Message] = []      # collect 队列
        self._inject: list[Message] = []       # steer 注入队列
        self._loop = AgentLoop(...)
    
    async def handle_message(self, msg):
        if self._running:
            if msg.priority == "steer":
                self._inject.append(msg)       # 立刻注入
            else:
                self._pending.append(msg)      # 排队等
            return
        await self._run_turn(msg)              # 不在运行，立刻开始
    
    async def _run_turn(self, trigger):
        self._running = True
        try:
            batch = [trigger] + self._pending
            self._pending.clear()
            await self._loop.run_one_turn(
                messages=batch,
                inject_queue=self._inject,
            )
        finally:
            self._running = False
            if self._pending:
                next_trigger = self._pending.pop(0)
                await self._run_turn(next_trigger)
```

#### AgentLoop 内部处理 inject_queue

```python
for step in range(max_steps):
    # ① 检查 steer 消息
    while self._inject_queue:
        msg = self._inject_queue.pop(0)
        ctx.add_user_message(f"{format_prefix(msg)}: {msg.content}")
    
    # ② 调 LLM（steer 消息已在上下文中）
    response = await self._brain.chat(ctx.messages, tools)
    
    # ③ 执行 tool calls
    for tc in response.tool_calls:
        result = await self._execute_tool(tc)
        ctx.add_tool_result(tc.id, result)
    
    # ④ 无 tool_calls → 本轮结束
    if not response.tool_calls:
        break
```

POST /api/agents/alice/message

## 6. 模块四：Agent 生命周期与进程模型

### 6.1 进程模型

每个 agent 一个独立进程，被 sandbox-exec 隔离。沿用 v3.1/v3.2 的 UDS + worker.py。

核心变化：worker 从 run-to-completion（跑完退出）变成 recv loop（跑完等下一条消息）。

### 6.2 Agent 状态

```
created → idle ⇄ running → idle
                    ↓
                  error → idle
```

### 6.3 agent 进程主循环

```python
async def agent_main(agent_id, sock_path):
    client = UDSClient(sock_path)
    await client.connect()
    runtime = AgentRuntime(agent_id, client)
    
    while True:
        raw = await client.recv()   # 阻塞等消息，零CPU
        msg = Message.from_json(raw)
        if msg.source == "system" and msg.content == "shutdown":
            break
        await runtime.handle_message(msg)  # collect/steer
```

### 6.4 启动方式

| 方式 | 场景 |
|------|------|
| server 启动时 | auto_start: true 的 agent 随 server 启动 |
| 按需启动 | 用户给 agent 发第一条消息时自动启动 |
| 手动启动 | 前端 "Start" 或 POST /api/agents/{id}/start |

### 6.5 心跳

Server 进程持有 heartbeat 定时器，每 N 分钟给配置了心跳的 agent 发一条 heartbeat 消息。
Agent 收到后走正常 run_one_turn() 流程。

### 6.6 AgentSupervisor

```python
class AgentSupervisor:
    def __init__(self):
        self._processes: dict[str, subprocess.Popen] = {}
        self._uds_connections: dict[str, UDSConnection] = {}
    
    async def start_agent(self, agent_id):
        if agent_id in self._processes:
            return
        sock_path = RUN_DIR / f"{agent_id}.sock"
        sandbox_profile = generate_sandbox(agent_id)
        proc = subprocess.Popen([
            "sandbox-exec", "-f", str(sandbox_profile),
            sys.executable, "-m", "see_agent.agent.worker",
            "--agent-id", agent_id,
            "--sock", str(sock_path),
        ])
        self._processes[agent_id] = proc
        conn = await UDSConnection.accept(sock_path)
        self._uds_connections[agent_id] = conn
    
    async def send_to(self, agent_id, msg):
        if agent_id not in self._processes:
            await self.start_agent(agent_id)  # 按需启动
        conn = self._uds_connections[agent_id]
        await conn.send(msg.to_json())
    
    async def stop_agent(self, agent_id):
        await self.send_to(agent_id, Message(source="system", content="shutdown", ...))
        self._processes[agent_id].wait(timeout=30)
        del self._processes[agent_id]
        del self._uds_connections[agent_id]
```

## 7. 模块五：消息路由（Server 做邮局）

Server 进程是中心化邮局：agent 进程之间不直接通信，所有消息经 server 中转。
原因：agent 进程被 sandbox 隔离，看不到彼此。

### 7.1 路线一：User → Agent

```
用户浏览器 → POST /api/agents/alice/message { content, priority }
    │
    ▼
Server 进程
    │ AgentSupervisor.send_to("alice", msg)
    │ → 找 alice 的 UDS 连接
    │ → UDS send: { source:"user", sender:"lanxuan", content, priority }
    │
    ▼ UDS socket
Alice 进程（sandbox 内）
    │ recv() 收到消息
    │ running?
    │ → 否：run_one_turn()，注入 "[user lanxuan]: ..."
    │ → 是+steer：inject 队列，下一步 LLM 就看到
    │ → 是+collect：pending 队列，等当前 loop 结束
    │
    │ loop 完成后 UDS send 回复给 server
    ▼
Server 进程 → WS 推送给浏览器 + 写 session JSONL
```

### 7.2 路线二：Team Agent → Team Agent

```
Alice 的 loop 调用 send_message(to="bob", content="代码写好了")
    │
    ▼
Alice 进程 → UDS send: { method:"bus.send", params:{ to:"bob", content, priority } }
    │
    ▼ UDS socket
Server 进程
    │ ① 判断 alice 的角色
    │    alice == team.leader? → source="leader" 否则 source="teammate"
    │ ② 写入 teams/{id}/messages.jsonl（审计日志）
    │ ③ 找 bob 的 UDS 连接
    │ → UDS send to bob: { source:"leader", sender:"alice", content, priority }
    │ ④ WS 广播给前端
    │
    ▼ UDS socket
Bob 进程（sandbox 内）
    │ recv() 收到消息
    │ running?
    │ → 否：run_one_turn()，注入 "[leader alice]: 代码写好了"
    │ → 是+steer：inject 队列
    │ → 是+collect：pending 队列
    ▼
```

### 7.3 路线三：Team Worklist → Team Agent

```
场景 A：Leader 分配任务
Alice(leader) 调 assign_task(task_id="t-001", to="bob")
    │
    ▼
Alice 进程 → UDS: { method:"board.assign", params:{ task_id, assigned_to:"bob" } }
    │
    ▼ UDS
Server 进程
    │ ① 更新 teams/{id}/tasks.jsonl：t-001 status→assigned, to:bob
    │ ② 给 bob 发消息（走 UDS，同路线二）
    │    { source:"task", sender:"system",
    │      content:"任务分配: [t-001] 测试登录流程\n分配者: alice(leader)" }
    │ ③ WS 广播 task_update 给前端
    │
    ▼ UDS
Bob 进程
    │ 收到 [task] 消息
    │ → collect/steer 处理
    │ → LLM 看到任务，决定怎么做

场景 B：Agent 主动领取
Bob 调 claim_task(task_id="t-002")
    │
    ▼
Bob 进程 → UDS: { method:"board.claim", params:{ task_id:"t-002" } }
    │
    ▼ UDS
Server 进程
    │ ① 更新 tasks.jsonl
    │ ② 返回 task 详情给 bob
    │ ③ WS 广播 task_update
    │ （不需要通知别人，是 bob 主动领的）
```

### 7.4 MessageRouter 职责

```python
class MessageRouter:
    """Server 进程的消息路由中心。"""
    
    async def on_agent_rpc(self, caller_agent_id, method, params):
        """处理 agent 进程通过 UDS 发来的 RPC 请求。"""
        
        if method == "bus.send":
            to = params["to"]
            content = params["content"]
            priority = params.get("priority", "normal")
            
            # 判断 caller 是否为 leader
            team = self._find_common_team(caller_agent_id, to)
            if team and team.leader == caller_agent_id:
                source = "leader"
            else:
                source = "teammate"
            
            msg = Message(source=source, sender=caller_agent_id,
                          content=content, priority=priority)
            
            # 写审计日志
            if team:
                self._append_team_log(team.id, msg)
            
            # 转发
            await self._supervisor.send_to(to, msg)
            
            # WS 广播
            await self._broadcast_ws(team.id if team else None, msg)
        
        elif method == "board.assign":
            task_id = params["task_id"]
            assigned_to = params["assigned_to"]
            self._task_board.assign(task_id, assigned_to)
            
            # 给被分配者发消息
            task = self._task_board.get(task_id)
            msg = Message(source="task", sender="system",
                          content=f"任务分配: [{task.id}] {task.title}")
            await self._supervisor.send_to(assigned_to, msg)
            
            # WS 广播
            await self._broadcast_ws_task_update(task)
        
        elif method == "board.claim":
            ...
        elif method == "screen.acquire":
            ...
```

### 8.1 Team 的新定位

Team 是一个"房间"，不是 agent 的管理器。

| v3.2 | v3.5 |

| TeamManager.run(task) 唯一入口 | 可独立运行，可组团 |

### 8.2 Agent 加入 team 后多出的能力

| 共享任务板 | teams/{id}/tasks.jsonl |
| 屏幕租约 | 通过 ScreenManager 协调 |

# 加入：修改 team.json，agent 自动获得协作 tool + team context

team.save()

agent 的 workspace、session、memory 全程不搬迁。
