## 1. 记忆系统重做

### 1.1 现状问题

- `memories.jsonl` 把整个对话（含系统提示词、环境信息）粗暴 dump，噪音极大
- 中文搜索用 `str.split()`（按空格），对中文完全无效
- agent 没有主动管理记忆的 tool，记忆全靠系统自动写入

### 1.2 新设计（参考 OpenClaw）

**记忆 = 纯 Markdown 文件，agent 自己写。**

每个 agent 目录下：

```
agents/{id}/
├── AGENTS.md                    ← 行为准则（模板，首次创建时复制）
├── SOUL.md                      ← 人格描述
├── memory/
│   ├── MEMORY.md                ← 长期记忆（agent 自己维护，提炼精华）
│   ├── 2026-03-10.md            ← 日记（agent 自己决定是否写）
│   └── 2026-03-09.md
└── ...
```

### 1.3 AGENTS.md 模板

每个 agent 创建时自动生成 `AGENTS.md`（从 `see_agent/templates/AGENTS.md` 复制）：

```markdown
# AGENTS.md — 行为准则

## 记忆管理

你的记忆存储在 memory/ 目录下：
- `memory/MEMORY.md` — 长期记忆，定期从日记中提炼重要信息
- `memory/YYYY-MM-DD.md` — 日记，记录当天重要的决策、发现、问题

### 什么时候写记忆
- 完成重要任务后，写总结到日记
- 学到新知识或发现规律时
- 用户明确说"记住这个"时
- 不要每个小任务都写，自己判断重要性

### 什么时候读记忆
- 任务开始时，用 memory_search 搜索相关记忆
- 需要回忆之前做过什么时

## 团队协作

- 收到 leader 消息优先处理
- 完成任务后及时汇报
- 遇到困难主动沟通，不要死磕

## 安全

- 不执行危险命令（rm -rf 等）
- 不泄露密码、密钥
- 不确定就问
```

### 1.4 记忆 Tool

给 agent 提供两个 tool：

#### `memory_search` — 搜索记忆

```python
class MemorySearchTool(Tool):
    """搜索 agent 的记忆文件（MEMORY.md + memory/*.md）"""
    name = "memory_search"
    description = "搜索你的记忆，找到之前记录的相关信息"
    parameters = {
        "query": {"type": "string", "description": "搜索关键词或问题"}
    }

    async def execute(self, query: str) -> ToolResult:
        results = self._backend.search(query, limit=5)
        if not results:
            return ToolResult(text="没有找到相关记忆。")
        text = "\n".join(f"- [{r['source']}] {r['snippet']}" for r in results)
        return ToolResult(text=f"找到 {len(results)} 条相关记忆：\n{text}")
```

#### `write_memory` — 写入记忆

```python
class WriteMemoryTool(Tool):
    """向记忆文件追加内容"""
    name = "write_memory"
    description = "记录重要信息到记忆文件"
    parameters = {
        "file": {"type": "string", "description": "文件名，如 MEMORY.md 或 2026-03-10.md"},
        "content": {"type": "string", "description": "要记录的内容（Markdown）"}
    }

    async def execute(self, file: str, content: str) -> ToolResult:
        # 校验：只允许写 MEMORY.md 或 YYYY-MM-DD.md
        if file != "MEMORY.md" and not re.match(r"^\d{4}-\d{2}-\d{2}\.md$", file):
            return ToolResult(text="只能写入 MEMORY.md 或日期格式的文件（如 2026-03-10.md）")
        path = self._memory_dir / file
        path.parent.mkdir(parents=True, exist_ok=True)
        with open(path, "a", encoding="utf-8") as f:
            f.write(content + "\n\n")
        return ToolResult(text=f"已写入 memory/{file}")
```

### 1.6 memoryFlush（上下文压缩前自动提醒）

在 AgentLoop 的 `_maybe_compact()` 中，compact 之前先触发 memoryFlush：

```python
async def _maybe_compact(self, ctx, session):
    # ... 估算 token 超过阈值 ...
    
    # 1. 先提醒 agent 保存记忆（静默：不发给 owner）
    ctx.add_system_message(
        "你的对话上下文即将被压缩。"
        "请把重要信息写入 memory/ 文件（用 write_memory 工具），"
        "然后继续你的工作。"
    )
    
    # 2. 让 agent 执行一轮（可能调用 write_memory）
    await self._run_one_step(ctx, session, silent=True)
    
    # 3. 执行 compact
    await self._do_compact(ctx, session)
```

`silent=True` 表示这一轮的 agent 回复不通过 bus 发给 owner，用户完全无感。

## 2. 像素办公室重做

### 2.1 现状问题

CC 用纯 CSS + div 画了一个网格布局，**完全没用 Phaser 3**：
- `phaser` 已安装（package.json 有），但代码里没有 import
- 没有像素背景图（`offices/` 和 `sprites/` 目录都是空的）
- 没有 agent sprite 动画
- 没有 3/6/12 人三种规格办公室
- 不是像素游戏风格

### 2.2 新设计

**用 Phaser 3 重做**，浏览器是窗口（viewport），办公室有自己的固定尺寸，可拖动查看。

#### 场景尺寸

| 规格 | members 数 | Phaser 场景尺寸 | 座位数 |
|------|-----------|----------------|--------|
| 小型 | ≤ 3 | 640 × 400 | 3 |
| 中型 | 4 ~ 6 | 960 × 500 | 6 |
| 大型 | 7 ~ 12 | 1280 × 640 | 12 |

浏览器给 Phaser 的区域 = 父容器宽度 × 60vh（Team 详情页上半部分），Phaser 填满容器。

#### Camera（视角）

- 办公室场景尺寸固定（不随浏览器缩放）
- Camera bounds = 场景尺寸
- 支持鼠标拖动平移（pointerdown + pointermove）
- 移动端支持触摸拖动
- 如果场景比 viewport 小（比如 3 人办公室 640×400 在大屏上），居中显示不需要拖

## 3. Agent 事件驱动循环

### 3.1 现状问题

目前 AgentLoop 是"跑一个 task 就结束"的模式。v3.1 改成子进程后，需要改为持续运行、事件驱动。

### 3.2 新设计

agent 子进程启动后进入**持续监听循环**，不退出：

```python
# worker.py 中的主循环
async def agent_event_loop(loop: AgentLoop, uds_client: UDSClient):
    """Agent 子进程的事件驱动主循环。"""
    
    shutdown_after_task = False
    
    while True:
        # 阻塞等待事件（零 CPU）
        event = await uds_client.recv()
        
        if event["type"] == "bus_message":
            # 队友/leader/owner 来消息了
            loop.inject_message(
                sender=event["data"]["sender"],
                content=event["data"]["content"]
            )
            # 唤醒 LLM 处理消息
            await loop.run_one_turn()
            
        elif event["type"] == "task_created":
            # 任务看板有新任务
            loop.inject_notification(
                f"新任务出现: [{event['data']['id']}] {event['data']['title']}"
            )
            await loop.run_one_turn()
            
        elif event["type"] == "task_assigned":
            # 被分配了任务
            task = event["data"]
            loop.inject_notification(
                f"你被分配了任务: [{task['id']}] {task['title']}"
            )
            await loop.run_one_turn()
            
        elif event["type"] == "screen_available":
            # 屏幕租约轮到你了
            loop.inject_notification("屏幕已可用，你现在可以操作屏幕了。")
            await loop.run_one_turn()
            
        elif event["type"] == "graceful_shutdown":
            if loop.is_busy():
                shutdown_after_task = True
                loop.inject_notification("收到重启指令，完成当前任务后将重启。")
            else:
                break
                
        elif event["type"] == "shutdown":
            break
        
        # 检查是否需要 graceful shutdown
        if shutdown_after_task and not loop.is_busy():
            break
```

### 3.3 run_one_turn() 和 run(task) 的区别

```python
class AgentLoop:
    async def run(self, task: str):
        """执行完整任务（直到 finished 或步数用完）——旧模式"""
        ...
    
    async def run_one_turn(self):
        """处理一轮：把当前上下文发给 LLM，执行 LLM 返回的 tool calls。
        可能连续执行多步（LLM 连续返回 tool_calls），
        直到 LLM 没有更多 tool_calls 或调用了 finished。
        """
        ...
    
    def inject_message(self, sender: str, content: str):
        """注入消息到对话上下文（不触发 LLM）"""
        self._context.add_user_reply(f"[{sender}]: {content}")
    
    def inject_notification(self, text: str):
        """注入系统通知（不触发 LLM）"""
        self._context.add_system_message(text)
```

### 3.4 Leader 的持续运作

Leader 和 Worker 的区别只在 prompt 和 tool 集，进程模型完全一样：

- Leader 有额外 tool：`create_task`, `assign_task`, `dismiss_agent`
- Leader 的 prompt 说"你负责分任务、协调进度"
- Worker 的 prompt 说"你接受 leader 分配的任务"

Leader 持续运作靠：
1. Worker 完成任务 → bus 消息 → leader 收到 → 继续协调
2. Owner 发新指令 → bus 消息 → leader 收到 → 继续工作
3. 没人说话 → 阻塞在 recv() → 零 CPU → 等有人说话

**Team 不会"停运"**，除非 owner 主动 stop 或所有任务都完成。

## 4. WebSocket 推送

### 4.1 需要实现的端点

`WS /api/ws/team/{team_id}` — 统一的 team 级 WebSocket，推送所有事件。

### 4.2 事件类型

```typescript
// 前端收到的 WebSocket 消息格式
type WsEvent = 
  | { type: "message",      data: { sender: string, recipient: string, content: string, ts: string } }
  | { type: "task_update",   data: { id: string, title: string, status: string, assigned_to: string } }
  | { type: "agent_step",    data: { agent_id: string, step: number, thought: string, tool: string } }
  | { type: "screen_lease",  data: { holder: string | null, queue_length: number } }
  | { type: "agent_status",  data: { agent_id: string, status: "idle" | "busy" | "offline" } }
```

### 4.3 后端实现

主进程在 Bus/TaskBoard/ScreenManager 变更时广播到 WS 连接：

```python
# server/routes/ws_team.py
@router.websocket("/api/ws/team/{team_id}")
async def team_ws(websocket: WebSocket, team_id: str):
    await websocket.accept()
    # 注册到广播列表
    broadcast_list = app.state.ws_connections.setdefault(team_id, [])
    broadcast_list.append(websocket)
    try:
        while True:
            await websocket.receive_text()  # 保持连接（也可以接收客户端消息）
    except WebSocketDisconnect:
        broadcast_list.remove(websocket)

# 广播函数（Bus/TaskBoard/ScreenManager 调用）
async def broadcast_to_team(team_id: str, event: dict):
    connections = app.state.ws_connections.get(team_id, [])
    for ws in connections:
        try:
            await ws.send_json(event)
        except:
            pass  # 连接已断开
```

## 5. Agent 加入/离开 Team 完整流程

### 5.1 加入 Team

1. 前端操作"把 alice 加入 team-a"
2. `POST /api/agents/alice/assign` body: `{"action": "join", "team_id": "team-a"}`
3. 后端：
   - 搬目录 `agents/alice/` → `teams/team-a/agents/alice/`
   - 更新 `team.json` 的 members
   - 如果 team 正在运行 → 启动 alice 子进程
   - 在 TaskBoard 创建 onboarding 任务：
     ```json
     {"title": "欢迎 alice 加入团队", "type": "onboarding", "target_agent": "alice", "assigned_to": "leader"}
     ```
   - 通过 bus 通知 leader

### 5.2 离开 Team

1. 前端操作"把 alice 移出 team-a"
2. `POST /api/agents/alice/assign` body: `{"action": "leave", "team_id": "team-a"}`
3. 后端：
   - 在 TaskBoard 创建 offboarding 任务：
     ```json
     {"title": "办理 alice 退出团队", "type": "offboarding", "target_agent": "alice", "assigned_to": "leader"}
     ```
   - 通过 bus 通知 leader
4. leader 执行 offboarding：
   - 和 alice 对话，了解工作进展
   - 消化 shared workspace 中 alice 的成果
   - 记录 alice 的工作经验
   - 调用 `dismiss_agent` tool
5. `dismiss_agent` tool 后端实现：
   - 搬目录 `teams/team-a/agents/alice/` → `agents/alice/`（memory 跟走，workspace 不跟）
   - 更新 team.json members
   - 终止 alice 子进程

### 5.3 新增 Tool

`dismiss_agent` — 只有 leader 能用的 tool：

```python

    description = "将 agent 移出团队。请在完成交接后使用。"
```

## 7. Agent 优雅重启

### 7.1 API

`POST /api/teams/{team_id}/agents/{agent_id}/restart`

### 7.2 流程

1. 主进程通过 UDS 发送 `graceful_shutdown` 事件
2. agent 子进程：
   - 如果空闲 → 立即退出
   - 如果在执行任务 → 标记"完成后退出" → 完成当前任务后退出
3. 主进程等待子进程退出（最多 5 分钟）
4. 用新配置重新启动子进程

### 7.3 前端

Agent 详情页 / Team 详情页加"重启 agent"按钮：
- 点击 → 按钮变为"等待 agent 完成当前任务..."
- 重启完成 → 提示"agent 已重启"

## 9. 配置热重载

### 9.1 需求

修改 config.json 后部分配置立即生效，不需要重启服务。

### 9.2 设计

| 配置 | 热重载？ | 说明 |
|------|---------|------|
| LLM base_url / api_key / model | ✅ 热重载 | 每次 LLM 调用时重新读 config |
| language | ✅ 热重载 | 下次构建 prompt 时读 |
| max_steps / tool_delay_ms | ✅ 热重载 | 下次任务开始时读 |
| memory.search.embedding | ✅ 热重载 | 下次 memory_search 时读 |
| 端口号 | ❌ 需重启 | launchd 绑端口 |
| agent.json | ⚠️ 需重启 agent | `POST .../restart` |
| sandbox 权限 | ⚠️ 需重启 agent | `POST .../restart` |

### 9.3 实现

config.py 的 `load_config()` 改为每次都从文件读取（不缓存在内存），或者用 file watcher + 缓存失效：

```python
_config_cache: dict | None = None
_config_mtime: float = 0

def load_config() -> dict:
    """读取 config.json。文件修改后自动刷新缓存。"""
    global _config_cache, _config_mtime
    mtime = CONFIG_PATH.stat().st_mtime
    if _config_cache is None or mtime > _config_mtime:
        _config_cache = json.loads(CONFIG_PATH.read_text())
        _config_mtime = mtime
    return _config_cache
```
