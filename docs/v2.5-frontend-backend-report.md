## 2. 需要新增的 API

### 2.1 P0 — 没有就跑不起来

#### `GET /api/agents` — 全局 Agent 列表

**说明**：前端 Agents 栏目需要展示所有 agent，包括待岗（`~/.see-agent/agents/`）和在岗（`~/.see-agent/teams/*/agents/`）。

**返回**：
```json
[
  {
    "id": "alice",
    "name": "Alice",
    "role": "前端工程师",
    "team_id": "abc123",        // null 表示待岗
    "team_name": "周报任务",     // null 表示待岗
    "status": "idle"             // idle | busy | offline
  }
]
```

**实现**：新增 `AgentDefinition.list_all_global()` 方法，遍历 `AGENTS_DIR` + 所有 `TEAMS_DIR/*/agents/`。

#### `GET /api/agents/{id}` — Agent 详情

**说明**：返回完整 agent 信息，包括 agent.json 内容、所属 team、SOUL.md 是否存在。

**返回**：
```json
{
  "id": "alice",
  "name": "Alice",
  "role": "前端工程师",
  "config_overrides": {},
  "tools_config": {},
  "skills_config": {},
  "mcp_config": {},
  "team_id": "abc123",
  "team_name": "周报任务",
  "has_soul": true,
  "location": "teams/abc123/agents/alice"   // 实际目录位置
}
```

**实现**：先从 `AGENTS_DIR` 查找，没找到则遍历 `TEAMS_DIR/*/agents/`。返回时动态计算所属 team。

#### `POST /api/agents` — 创建 Agent

**Body**：
```json
{
  "id": "alice",
  "name": "Alice",
  "role": "前端工程师",
  "soul": "你是 Alice，一个前端工程师..."   // 可选，写入 SOUL.md
}
```

**实现**：调用 `AgentDefinition.create()`，如果传了 `soul` 则写入 `SOUL.md`。

#### `PUT /api/teams/{id}` — 编辑 Team 配置

**Body**：team.json 的部分字段更新（deep merge）。
```json
{
  "name": "新名字",
  "overrides": { ... },
  "seating": { "alice": 0, "bob": 1 }   // 座位映射
}
```

**实现**：load → merge → save。

#### `GET /api/schemas/{type}` — JSON Schema

**参数**：`type` = `config` | `agent` | `team`

**返回**：对应的 JSON Schema 文件内容。前端用 rjsf 渲染表单。

**实现**：
- 在 `see_agent/schemas/` 目录下创建三个 schema 文件
- 新增路由读取并返回

#### `GET /api/logs` — 全局日志

**Query**：`?date=2026-03-10&level=ERROR&limit=500&offset=0`

**返回**：
```json
{
  "date": "2026-03-10",
  "lines": [
    "10:30:01  INFO      see_agent.server  Started on 0.0.0.0:8000",
    "10:30:05  WARNING   see_agent.agent   ...",
  ],
  "total": 1234
}
```

**实现**：读取 `~/.see-agent/logs/YYYY-MM-DD.log`，支持分页和级别过滤。

#### `GET /api/dashboard` — 全局统计

**返回**：
```json
{
  "teams": { "total": 3, "running": 1, "completed": 2 },
  "agents": { "total": 5, "in_team": 4, "idle": 1 },
  "tasks": { "total": 12, "pending": 2, "done": 10 },
  "recent_activity": [
    { "type": "team_completed", "team": "周报任务", "ts": "..." },
    { "type": "agent_created", "agent": "charlie", "ts": "..." }
  ]
}
```

**实现**：遍历 teams + agents + tasks.json 汇总。

### 2.2 P1 — 核心体验

#### `DELETE /api/teams/{id}` — 删除 Team

**实现**：删除 `TEAMS_DIR/{id}/` 目录。注意：如果 team 内还有 agent，需要先把 agent 目录移回 `AGENTS_DIR`（自动退团）。

#### `DELETE /api/agents/{id}` — 删除 Agent

**实现**：删除 agent 目录。如果在 team 内，需要同时从 team.json 的 members 中移除。

#### `GET /api/agents/{id}/soul` — 读取 SOUL.md

**返回**：`{ "content": "你是 Alice..." }`

#### `PUT /api/agents/{id}/soul` — 写入 SOUL.md

**Body**：`{ "content": "新的 SOUL 内容..." }`

**实现**：定位 agent 的实际目录（可能在 agents/ 或 teams/*/agents/），写入 SOUL.md。

#### `POST /api/agents/{id}/assign` — Agent 分配到 Team

**Body**：
```json
{
  "action": "join",       // join | leave
  "team_id": "abc123"
}
```

**join 实现**：
1. 将 `AGENTS_DIR/{id}/` 整个目录移动到 `TEAMS_DIR/{team_id}/agents/{id}/`
2. 更新 team.json 的 members 数组

**leave 实现**：
1. 将 `TEAMS_DIR/{team_id}/agents/{id}/` 移动到 `AGENTS_DIR/{id}/`
2. **workspace 不跟人走**（留在 team 的 shared/ 或直接留在原地）
3. 从 team.json 的 members 中移除
4. 给 Leader 创建一个"办理离职"任务（如果 team 正在运行）

**注意**：P1 阶段先实现静默搬迁。Leader 离职流程 P2 做。

#### `GET /api/mcp` — MCP Server 列表

**返回**：从 config.json 的 `mcp_servers` 读取，附加使用情况。
```json
[
  {
    "name": "filesystem",
    "command": "npx",
    "args": ["-y", "@mcp/filesystem"],
    "used_by": ["alice", "bob"]    // 哪些 agent 启用了
  }
]
```

#### `POST /api/mcp` — 添加 MCP Server

**Body**：
```json
{
  "name": "browser",
  "command": "npx",
  "args": ["-y", "@mcp/browser"],
  "env": {}
}
```

**实现**：更新 config.json 的 `mcp_servers` 字段。

#### `DELETE /api/mcp/{name}` — 删除 MCP Server

**校验**：检查是否有 agent 的 mcp_config 中引用了该 server。如有，返回 409 + 引用列表。

**实现**：从 config.json 的 `mcp_servers` 中删除该条目。

#### `GET /api/skills/{name}` — Skill 详情

**返回**：
```json
{
  "name": "open-browser",
  "description": "...",
  "body": "SKILL.md 完整内容...",
  "path": "/Users/.../skills/open-browser/SKILL.md",
  "available": true,
  "used_by": ["alice"]
}
```

#### `GET /api/teams/{id}/agents/{aid}/sessions` — Team 内 Agent Session 列表

**返回**：列出 `teams/{id}/agents/{aid}/sessions/` 下的 session 目录。

### 2.3 P2 — 锦上添花

| API | 方法 | 说明 |
|-----|------|------|
| `DELETE /api/skills/{name}` | DELETE | 删除 skill（带引用校验） |

## 3. 需要删除/清理的

### 3.1 多余的 API

| API | 文件 | 原因 | 处理 |
|-----|------|------|------|
| `POST /api/chat` | chat.py | 单 agent 运行。v2.5 设计"team 是唯一运行单元"，单 agent = 单人 team | **保留但标注 deprecated**，或改为内部自动创建单人 team |
| `POST /api/chat/{task_id}/message` | chat.py | 同上 | 保留，owner 消息走 team API |
| `GET /api/task/{task_id}` | task.py | 和 team status 功能重叠 | 保留（chat 模式仍在用） |
| `GET /api/sessions` + 子路由 | sessions.py | session 概念现在归属于 team/agent | **暂保留**，但前端不直接用；team 内 agent session 用新 API |

**结论**：chat.py / task.py / sessions.py 暂不删除，但在前端设计中不依赖这些路由。后续统一到 team 模式后可废弃。

### 3.2 多余的目录/文件

| 路径 | 原因 | 处理 |
|------|------|------|
| `workspace/` （项目根目录下） | 只有一个 `SOUL.md`（默认模板），应该放在包内 | **删除目录**，SOUL.md 模板移到 `see_agent/templates/SOUL.md`（已在 config.py 中有 `_TEMPLATE_DIR`） |
| `assets/` （项目根目录下） | **空目录** | **删除** |
| `scripts/check.sh` | 包含 ruff + pytest 的检查脚本 | **保留**（有用），但 `scripts/` 目录可考虑迁移到 Makefile |
| `.env.example` | 示例环境变量 | **保留** |
| `see_agent/overlay/` | PyObjC 透明窗口 overlay | **保留**（核心功能） |
| `see_agent/plugin/` | 插件钩子系统 | **保留**（v2.5 设计有插件体系） |

### 3.3 源码逻辑清理

| 问题 | 文件 | 处理 |
|------|------|------|
| `AgentDefinition.load()` 只从 `AGENTS_DIR` 读 | agent/definition.py | 新增 `load_from(path)` 方法 + `list_all_global()` 遍历两处 |
| `AgentDefinition.save()` 只写到 `AGENTS_DIR` | agent/definition.py | 新增 `save_to(path)` 方法，支持指定目录 |

## 5. 路由文件重组建议

当前 `server/routes/` 结构：

```
routes/
├── __init__.py
├── agents.py      ← 只有 PUT，太简陋
├── chat.py
├── health.py
├── misc.py        ← tools + skills + config 混在一起
├── sessions.py
├── task.py
├── team.py
└── ws.py
```

**建议重组为**：

```
routes/
├── __init__.py
├── agents.py      ← GET 列表 + GET 详情 + POST 创建 + PUT 编辑 + DELETE + SOUL 读写 + assign
├── chat.py        ← 保留（legacy 单 agent 模式）
├── config.py      ← GET/PUT config + GET schemas
├── dashboard.py   ← GET dashboard 统计
├── health.py      ← 保留
├── logs.py        ← GET logs + WS logs（新）
├── mcp.py         ← GET/POST/DELETE mcp + POST test
├── sessions.py    ← 保留（legacy）
├── skills.py      ← GET 列表 + GET 详情 + DELETE
├── task.py        ← 保留（legacy）
├── teams.py       ← 重命名 team.py → teams.py，新增 PUT/DELETE
├── tools.py       ← GET tools 列表
└── ws.py          ← 保留
```

**核心原则**：一个栏目对应一个路由文件。

## 8. 设计约束提醒

1. **Agent 目录结构一致**：`~/.see-agent/agents/{id}/` 和 `~/.see-agent/teams/{team_id}/agents/{id}/` 内部结构完全相同
2. **加入 team = 整目录搬入**，memory 跟人走，workspace 不跟
3. **撤出 team 需要 Leader 办理**（P2 实现，P1 先静默搬迁）
4. **JSON Schema 只有一份**，放在 `see_agent/schemas/` 包内，随 pip 升级
5. **像素办公室规格**：3人 / 6人 / 12人，前端根据 members 数自动匹配
6. **座位映射**：`seating` 字段持久化在 team.json 中
7. **前端配置表单**：统一用 rjsf + schema，config / agent / team 三种 schema 不同但组件相同
8. **Skill 和 MCP 的增删**：前端触发后端 API，后端执行文件操作（或调 CLI）
9. **Logs 按层级分离**：全局日志在 Logs 栏目看，team/agent 日志在各自详情页看
