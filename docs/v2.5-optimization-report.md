## 1. 已知 Bug（🫐可能已修复部分）

### Bug 1（P0）：Bus→Loop 桥接断开

**现状**：TeamManager 创建了 user_queue 并传给 AgentLoop，也创建了 TeamBus，但 bus 中的消息没有自动流入 agent 的 user_queue。agent 无法收到队友消息。

**修复**：需要一个桥接机制，定期（或事件驱动）把 bus.drain(agent_id) 的消息格式化后塞入 user_queue：

```python
# 格式化为带前缀的 user message
for msg in bus.drain(agent_id):
    prefix = f"[teammate {msg.sender}]" if msg.sender != "owner" else f"[{owner_display}]"
    user_queue.put_nowait(f"{prefix}: {msg.content}")
```

### Bug 2（P0）：Screen Lock 没有串联到 tool 执行

**现状**：TeamManager 声明了 `self._screen_lock = asyncio.Lock()`，但没传给 AgentLoop，也没在 tool 执行时 acquire。

**修复**：screen_lock 传给 AgentLoop，在需要屏幕的 tool（screenshot, click, type_text, scroll, drag, hotkey）执行时 acquire。判断方式：给 Tool 基类加 `requires_screen: bool = False` 属性，屏幕操作类 tool 设为 True。

```python
async def _execute_tool(self, tool, args):
    if self._screen_lock and tool.requires_screen:
        async with self._screen_lock:
            return await tool.run(args)
    return await tool.run(args)
```

## 2. 新增需求：Owner 身份与用户通信

### 2.1 设计

用户（owner）是 team 的特殊参与者，不是 agent，但有 bus 身份，可以和任何 agent 通信。

### 2.2 team.json 新增 owner 字段

```jsonc
{
  "id": "weekly-report-20260309",
  "members": ["leader", "alice", "bob"],
  "leader": "leader",
  "owner": {
    "name": "lanxuan",
    "display": "老板"         // agent 看到的消息前缀
  }
}
```

### 2.3 TeamBus 注册 owner

TeamManager 启动时自动注册：

```python
bus.register("owner")
```

bus id 固定为 `"owner"`，display name 从 team.json 读取。

### 2.4 消息权限规则

| 发送方 | 接收方 | 是否允许 |
|--------|--------|---------|
| owner | 任何 agent | ✅ 随时 |
| leader | owner | ✅ 主动汇报 |
| worker | owner | ⚠️ 仅回复（owner 先给该 worker 发过消息才能回） |

在 SendMessageTool 中实现权限检查：

```python
if to == "owner" and sender != leader_id:
    if not bus.has_prior_message(from_="owner", to=sender):
        return "你不能主动给 owner 发消息，请通过 leader 汇报。"
```

TeamBus 需要新增 `has_prior_message(from_, to)` 方法，从 messages.jsonl 中检查。

### 2.5 消息注入格式

```
来自 owner：  [老板]: 先做登录页面
来自 leader： [teammate leader]: 任务分配给你了
来自 worker： [teammate alice]: API 字段是 name, email
```

owner 的 display name 从 team.json 的 `owner.display` 读取。

### 2.6 Agent prompt 中的协作规则更新

```
## 协作规则
- [老板] 是 team 的所有者，优先处理其消息
- [teammate xxx] 是你的队友
- 用 send_message 工具和队友或老板沟通
- Leader 可以随时给老板汇报
- Worker 只能回复老板主动发来的消息
```

### 2.7 未读状态

新增文件 `teams/<team_id>/owner_state.json`：

```jsonc
{
  "last_read_ts": "2026-03-09T18:00:00+08:00"
}
```

未读计数通过 messages.jsonl 中 `recipient == "owner"` 且 `ts > last_read_ts` 的消息数计算，不需要额外存储 unread_by_agent。

## 4. Loop 适配优化

### 4.1 初始截图优化

**现状**：loop.run() 启动就截屏，team 模式下 leader（纯协调角色）不需要截图。

**修复**：判断 agent 是否有屏幕操作类 tool（screenshot, click 等），没有则跳过初始截图。不加配置项。

```python
screen_tools = {"screenshot", "click", "type_text", "scroll", "drag", "hotkey"}
agent_tools = {t.name for t in registry.get_all()}
if not screen_tools.intersection(agent_tools):
    screenshot = None  # 跳过初始截图和环境信息收集
```

### 4.2 Environment 收集去重

**现状**：每个 agent 启动时都调 `collect_environment()`，team 模式下重复 N 次。

**修复**：TeamManager 启动时收集一次，通过配置传给所有 AgentLoop。

```python
# TeamManager.run()
env_block = await collect_environment(...)
for agent_id in members:
    loop = self._build_agent_loop(agent_id, env_block=env_block)
```

### 4.3 call_user tool 改造

**现状**：`call_user` tool 阻塞等待 stdin 输入，team 模式下不可用。

**修复**：team 模式下，call_user 改为通过 bus 发消息给 owner，然后返回提示"已向老板提问，请继续其他工作，等待回复"。不阻塞。

```python
class CallUserTool(Tool):
    async def run(self, question: str):
        if self._bus:  # team 模式
            self._bus.send(BusMessage(
                sender=self._agent_id,
                recipient="owner",
                content=f"[提问] {question}",
            ))
            return "已向老板提问，请继续其他工作。收到回复后会通知你。"
        else:
            # 原有逻辑：stdin 阻塞
            return await self._ask_stdin(question)
```

### 4.4 finished tool 适配

**现状**：`finished` tool 终止当前 AgentLoop。team 模式下需要确认行为正确。

**确认**：当前 finished 只终止调用它的 agent 的 loop，TeamManager 用 `asyncio.gather` 等所有 agent 结束。这个行为是正确的，不需要改。但建议 finished 时同时在 TaskBoard 上标记该 agent 的所有 claimed 任务为 done（如果还没标的话）。

## 9. 设计约束提醒

1. **team 是唯一运行单元**：所有操作都在 team 中，单 agent 就是单人 team
2. **tool 全局注册、配置过滤**：team tools（send_message 等）也是全局注册的内置 tool
3. **owner 不是 agent**：不跑 AgentLoop，只有 bus 身份和消息通道
4. **目录即数据库**：所有状态用 JSON/JSONL，无外部数据库
5. **代码路径唯一**：不存在 team 模式 / 非 team 模式的分叉，只有 team
